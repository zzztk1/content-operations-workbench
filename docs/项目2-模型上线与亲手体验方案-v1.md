# 项目2-模型上线与亲手体验方案-v1

最后更新：2026-04-11

## 1. 这一步的目标

模型上线这一步，不是直接把项目2包装成“大规模生产系统”，而是分成两步：

1. 先把项目2上线成一个你自己能亲手体验的本地服务
2. 再把它上线成一个你可以对外演示的云端服务

项目2当前最适合上线的对象，不是“单独一个模型”，而是：

> 一套以 FastAPI 为入口、以 LangGraph 工作流为核心、以 PostgreSQL Checkpointer 为状态层的内容工作流服务

也就是说，真正上线的是一套 API + 工作流系统，而不是一段 prompt。

## 2. 应该上线到哪里

### 第一阶段：本地可体验环境

先上线到本地，是因为这一步最重要的是：

- 你能亲手体验
- 你能看真实链路
- 你能自己复盘问题

当前本地体验入口已经有：

- `/health`
- `/docs`
- `/demo`
- `/v2/run`
- `/v2/run/stream`

### 第二阶段：云端演示环境

如果后面要对外展示，我建议先走：

- Render

原因：

- 更容易给出公网 URL
- 更适合现在这种 `FastAPI + env + Postgres` 的演示型系统
- 心智负担更低

如果后面想补更正式的云原生口径，再考虑：

- Google Cloud Run

## 3. 为什么这么上线

### 为什么先本地上线

因为你当前最重要的不是“讲我会部署云平台”，而是：

- 我真的用过这个系统
- 我看过它怎么跑
- 我知道它哪里会出问题

这对面试和复盘都更重要。

### 为什么再上 Render

因为项目2当前已经有：

- 健康检查
- 流式接口
- 前端体验页
- 状态持久化
- LangSmith 观测

所以它已经够资格做“演示型上线”，但还没必要一上来就做更重的平台化部署。

## 5. 这一步你要怎么亲手体验

### 5.1 启动服务

```bash
cd F:\codex\codex1\projects\media-agent\src
py -3 -m uvicorn api_v2:app --host 127.0.0.1 --port 8000
```

### 5.2 先看健康状态

打开：

- `http://127.0.0.1:8000/health`

你重点看：

- `status`
- `llm_provider_route`
- `image_model`
- `vision_model`
- `postgres_connectivity`

### 5.3 再看接口文档

打开：

- `http://127.0.0.1:8000/docs`

作用：

- 看接口是否都在
- 能不能手动调
- 请求结构和返回结构是不是清楚

### 5.4 最后打开体验页

打开：

- `http://127.0.0.1:8000/demo`

你在这里可以真实体验：

- 输入 brief
- 选平台和风格
- 切换自动 / 引导模式
- 切真实配图 / mock 配图
- 切真实视觉质检 / mock 视觉质检
- 看流式推进
- 看主图和候选图
- 看正文、标签和视觉质检结果

## 6. 这一步的验收标准

### 本地上线验收

至少满足：

1. `/health = 200`
2. `/docs` 可打开
3. `/demo` 可打开
4. `/v2/run` 可完成一次同步运行
5. `/v2/run/stream` 可看到 start / update / final
6. `run_id` 可回查
7. PostgreSQL 连通正常

### 演示上线验收

如果后面上 Render，至少满足：

1. 公网 `/health = 200`
2. 公网 `/demo` 可访问
3. 真实文本链路可跑
4. 真实图片链路可跑
5. 流式输出可用

## 7. 这一阶段的产品理解

项目2的“模型上线”，不是“把一个模型地址配出来”，而是：

- 把工作流系统变成可访问服务
- 把前后端打通
- 把健康检查、流式输出、状态持久化和观测能力一起带上

所以这一步更像：

> 工作流服务上线

而不是：

> 单模型上线

## 8. 最推荐的路线

当前最推荐你这样走：

1. 先完成本地可体验上线
2. 用 `/demo` 和 `/docs` 亲手体验
3. 确认文本、图片、视觉质检都可跑
4. 再做 Render 演示上线
