## 使用规则

任何写进简历的亮点，必须同时有：

1. 实现动作
2. 测量动作
3. 结果文件

## 当前不能直接写进简历的点

- 把「图文一致性」写成视觉模型级自动质检或已生产闭环（应写「启发式 / 关键词轻量检查」）
- 图片吞吐、成本降幅等数字不绑定具体报告与测试条件
- `LangSmith`：若写「全链路生产级可观测」，需自备口径；当前证据为远端 tracing 与 `matched_runs` 类结果文件
- `TTFT` 优化百分比：仅当明确引用对应 before/after 报告与场景时再写
- 多模型动态路由降本：当前无生产级多路由证据
- 图片并发收益：需引用 `latest_image_batch_compare_report.json` 及其实验条件，避免写成普适百分比

## 推荐简历表达

> 基于 LangGraph 构建多阶段内容工作流，拆分 research / writing / review-approval 子图，并接入 PostgreSQL Checkpointer 实现状态持久化与历史回查；通过 JSON Mode、手动解析与 Pydantic 提升结构化输出稳定性，补齐 /health、SlowAPI、熔断器、优雅关闭和 token 级 SSE 事件流，并沉淀 baseline vs v2 对比与功能审计结果文件；封面链路含多候选导出、图片文件级校验、串并行对比报告与启发式图文一致性检查（非视觉模型）。
