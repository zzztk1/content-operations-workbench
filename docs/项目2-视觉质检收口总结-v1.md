# 项目2 视觉质检收口总结 v1

最后更新：2026-04-11

## 1. 这轮完成了什么

- 在图片子图里新增 `review_cover_visual`
- 接入 StepFun 视觉模型 `step-1o-turbo-vision`
- 支持 `VISION_REVIEW_MOCK=true/false`
- 视觉质检结果已进入 state、导出包和 `/demo`
- 补了 mock / real / badcase 三类报告

- `theme_match_score`
- `readability_score`
- `composition_score`
- `overall_score`
- `passed`
- `risk_flags`
- `feedback`
- `review_mode`
- `vision_model`

### real
- 文件：`benchmarks/latest_visual_review_real_report.json`

  - 标题区域不可读
  - 构图混乱

## 4. 与配图模型基线的关系

- 封面生成默认与仓库正式性能基线对齐为 **`step-2x-large`**（见 `README.md`、`.env.example`、`benchmarks/latest_image_performance_baseline.json` 中的 `canonical_image_model`）。
- 视觉质检走 **`step-1o-turbo-vision`**（聊天视觉 API，与图片生成 endpoint 分离）。
- 个别历史 `benchmarks/latest_*.json` 或 `outputs/*.v2.json` 里仍可能出现旧版 `image_model` 字符串；以最近一次 **模型切换核验** 导出与 **`build_image_performance_baseline.py` 成功产物** 为准，不必手改旧日志类 JSON。

## 5. 当前最准确的项目口径

现在可以说：

“项目2已经接入视觉理解模型，对封面图执行主题一致性、可读性、构图和风险项质检，并形成 mock / real / badcase 三类验证结果。”

现在不要说：

- “视觉质检准确率 xx%”
- “图文一致性自动闭环”
- “图片质量问题自动修复”

## 6. 简历可升级点

可以升级成：

- “接入视觉理解模型实现封面图质检与图文一致性校验”

更稳的展开说法：

- “在封面生成后新增视觉质检节点，结合 `step-1o-turbo-vision` 输出主题一致性、可读性、构图与风险项评分，并以 mock / real / badcase 报告固化验证结果。”
