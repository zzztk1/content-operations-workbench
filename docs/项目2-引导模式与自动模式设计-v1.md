# 项目2 引导模式与自动模式设计（v1）

最后更新：2026-04-11

## 目标

- **自动模式 `auto`**：单次请求内从研究走到导出（与历史「一次跑通」一致）。  
- **引导模式 `guided`**：研究完成后进入 **等待选题**（`awaiting_topic_selection`），用户确认选题后再执行写作 → 配图与视觉质检 → 审核 → 导出。

## 状态字段

| 字段 | 类型 | 含义 |
|------|------|------|
| `run_mode` | `"auto"` \| `"guided"` | 本次运行模式 |
| `guided_topic_locked` | bool | 是否已确认选题；引导首段为 `false`，`continue` 成功后为 `true` |
| `status` | 含 `awaiting_topic_selection` | 引导首段结束、等待客户端提交选题索引 |

研究节点在 `guided` 且未锁定时 **不**将 `selected_topic` 写死为 `topics[0]`，仅填充 `research.topics` 供前端展示。

## 主图路由（概念）

`research_subgraph` 之后：

- `auto` → 进入写作子图  
- `guided` 且 `guided_topic_locked` → 进入写作子图  
- `guided` 且未锁定 → `topic_selection_stop` → 图结束，`status=awaiting_topic_selection`

## API（与 `api_v2.py` 一致）

| 端点 | 用途 |
|------|------|
| `POST /v2/run`、`POST /v2/run/stream` | 支持 `run_mode`；引导时首段在选题门结束 |
| `POST /v2/run/continue` | Body：**推荐** `run_id`（服务端从 checkpoint 加载 `state`）+ `selected_topic_index`；可显式传 `state`（兼容旧客户端）。`run_id` 与 `state` 同时存在时以 **`run_id` 为准** |
| `GET /v2/runs/{run_id}` | 读取暂停态或中间快照（主图 checkpointer） |

流式场景：引导暂停时，SSE 会收到含 `awaiting_topic_selection` 的 **`final`（或等价终态）事件**；前端应据此展示选题面板，并可调用 `GET /v2/runs/{run_id}` 刷新 `research.topics`（与 `demo_v2.html` 行为一致）。

## 续跑实现说明（边界）

继续执行在引擎内通过 **续跑子图**（从写作到导出）完成，入口状态来自 checkpoint 快照经选题补丁后的 `state`。因此：

- 引导「暂停」快照可通过 `GET /v2/runs/{run_id}` 读取（主图 checkpointer）。  
- **完成后**以 `POST /v2/run/continue` 的 JSON 响应为权威终态；若要求 `get_run` 与终态字节级一致，可后续演进为单图 `interrupt` / `Command` 统一线程（可选）。

## 错误与校验（接口层）

- `continue` 时若找不到 run：**404** `run not found`。  
- 若当前 `status` 不是 `awaiting_topic_selection`：**400**（提示先 `GET /v2/runs/{run_id}`）。  

## 后续升级（可选）

- 单图 + `interrupt_before` / `Command` 统一 checkpoint，使 `get_run` 全程一致。  
- 服务端按 `run_id` 缓存状态以减少客户端回传（需存储与鉴权设计）。
