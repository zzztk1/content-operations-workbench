## 4. 这轮没有被“彻底优化掉”的点

- 这轮 benchmark 里结构化稳定性已经明显提升，但性能没有同步提升。
- 当前真实 trade-off 很明确：
  - 平均延迟变高
  - completion token 变高
  - total token 变高
  - `TTFT` 变高

所以当前最安全的表达是：

> 结构化稳定性显著提升，但性能和 token 开销侧仍在继续优化。

## 5. 当前最适合写进简历的新增口径

### 第 2 条升级版

- 设计 `MetricsContext` 指标上下文管理器，统一采集节点级 token、延迟、错误数与成本口径状态，并结合 before / after 报告支持 prompt 调优和链路排障。

### 第 5 条升级版

- 基于 `JSON Mode + 手动解析 + Pydantic` 做真实模型评测与调优，将关键结构化节点的 `direct` 输出比例从 `11.11%` 提升到 `100%`。

注意：

- 这条只能写“结构化稳定性提升”。
- 不能顺手写成“性能更快”或“成本更低”。

## 6. 这轮最终结论

这轮真正留下来的，不是“所有数字都更漂亮”，而是两件更扎实的成果：

1. 把 `MetricsContext` 做成了真实工程能力。
2. 把 writer、reviewer 和 schema 的结构化稳定性做到了当前 benchmark 的 `100% direct`。

因此项目2当前最准确的口径是：

> 结构化输出稳定性和工程化指标采集能力继续增强，模型链路真实可跑、真实可测、真实可观测；但性能侧仍保持诚实表达，不硬写收益数字。
