# 项目2阶段2：数据准备

最后更新：2026-04-09

## 1. 这一步要解决什么问题

很多人会以为“数据准备”只属于训练项目，但项目2这种内容工作流系统，同样离不开数据。

这里的数据不是为了微调模型，而是为了 4 件事：

1. 给 research 和 writer 提供参考样本
2. 给 workflow（工作流）提供评测输入
3. 给后续优化留下 badcase（失败样本）
4. 给 before / after 对比留下 baseline（基线）结果

所以项目2的数据准备，本质上是在回答：

> 这个系统以后靠什么材料来写、测、改、证。

## 2. 先解释几个会反复出现的词

- `benchmark`（评测基准）：一组固定输入，用来反复测试系统效果。
- `baseline`（基线）：当前版本的参考结果，后面所有优化都拿它做对照。
- `before / after`：优化前 / 优化后对比。
- `badcase`（失败样本）：系统表现不好的典型例子，用来指导后续优化。
- `dataset`（数据集）：一批按某种规则整理好的输入材料。

## 3. 项目2需要准备哪些数据

项目2至少需要 4 类数据。

## 3.1 样本内容数据

作用：

- 给 research 和 writer 节点提供参考内容
- 让生成结果更像真实平台内容，而不是通用回答

项目2当前已有：

- `sample_posts/*.txt`

这些文件目前的价值是：

- 作为小红书风格样本
- 支撑 writer 节点做参考生成

当前不足：

- 样本类型还比较少
- 平台分布不够完整
- 还没有显式标注来源、风格、平台属性

## 3.2 Workflow benchmark 数据

作用：

- 给工作流固定输入，反复跑验证
- 检查不同版本在相同输入下的表现差异

项目2当前已有：

- `benchmarks/validate_workflow.py` 里的 3 条关键路径输入

目前已经覆盖：

- `approve`
- `needs_edit`
- `reject`

当前不足：

- 还偏少
- 只够功能基线，不够内容质量和工程能力评测

## 3.3 badcase 数据

作用：

- 记录系统在哪些输入上表现差
- 后面做 prompt、结构化输出、路由或工作流优化时有依据

项目2当前状态：

- 已有“低分 -> 重写”的逻辑
- 但还没有正式的 badcase 数据沉淀机制

后续建议：

- 把 review 分数低、重写次数多、结构化输出失败的案例沉淀成 badcase

## 3.4 baseline / compare 结果数据

作用：

- 为后续“结果型表述”提供证据
- 支撑简历里所有 before / after 提升

项目2当前已有：

- `benchmarks/latest_validation_report.json`

它现在能承担的角色是：

- 旧版功能 baseline

它现在还不能承担的角色是：

- 最终性能 baseline
- 流式输出 baseline
- JSON 结构稳定性 baseline

## 4. 当前项目2的数据资产盘点

## 4.1 已有数据资产

### A. 样本内容库

- `sample_posts/小红书爆款_*.txt`

### B. 功能验证输入

- `benchmarks/validate_workflow.py`

### C. 功能验证结果

- `benchmarks/latest_validation_report.json`

### D. 导出内容结果

- `outputs/*.json`
- `outputs/*.md`

## 4.2 这些资产现在分别能做什么

| 资产 | 当前用途 |
|---|---|
| `sample_posts` | 给 writer 提供参考样本 |
| `validate_workflow.py` | 作为 workflow 功能验证基线 |
| `latest_validation_report.json` | 作为旧版功能基线结果 |
| `outputs/*.json / *.md` | 作为导出格式参考和演示材料 |

## 5. 这一步为什么现在必须做

因为如果数据准备不先做，后面会出现 3 个问题：

1. 你不知道系统到底在拿什么做参考
2. 你后面没法做稳定的 before / after 对比
3. 你没有 badcase，优化就只能靠感觉

对于项目2来说，数据准备不是“补材料”，而是：

- 让模型应用有输入基础
- 让模型评测有对照基础
- 让后续优化有证据基础

## 6. 项目2接下来应该怎样扩数据

## 6.1 样本内容数据要怎么补

建议补 3 类信息：

- 平台：小红书 / 抖音 / 公众号
- 风格：种草 / 测评 / 知识科普 / 经验分享
- 主题：职场 / AI / 生活方式 / 消费决策

这样后面 writer 和 adapter 才更容易做平台化输出。

## 6.2 benchmark 数据要怎么补

除了现在的 3 条路径，还建议补：

- 高质量通过案例
- 多次重写案例
- 结构化输出失败案例
- 平台适配差异案例
- 长 brief / 短 brief 对比案例

## 6.3 badcase 怎么沉淀

后续至少记录 3 类 badcase：

- review 分数低于阈值
- JSON 解析失败
- fallback 被触发

## 7. 数据准备阶段的最小交付

这一步不要求你现在就把数据做很多，而是先把规则定住。

项目2数据准备的最小交付应该是：

1. 明确现在已有哪几类数据
2. 明确每类数据分别做什么
3. 明确哪些是 baseline，哪些是后续要补的
4. 明确 badcase 和 compare 以后往哪里沉淀

## 8. 本阶段验收标准

- 你能说清项目2的数据准备不是训练集准备，而是工作流系统的数据准备。
- 你能分清样本内容数据、benchmark 数据、badcase 数据和 baseline 结果数据。
- 你能说清当前 `sample_posts` 和 `latest_validation_report.json` 分别承担什么角色。
