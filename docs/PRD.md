## 1. 产品背景

### 1.1 行业现状

中国自媒体行业已进入精细化运营时代。据统计，2025年中国自媒体从业者超过**1500万人**，覆盖小红书、抖音、微信公众号、B站等主流内容平台。内容创作已从"有就行"进化到"优质内容才能突围"的竞争格局。

### 1.2 痛点分析

| 痛点 | 描述 | 影响 |
|------|------|------|
| **选题效率低** | 运营人员每日花费30-60分钟浏览各平台热点，凭经验判断选题 | 时间浪费，选题质量不稳定 |
| **内容创作慢** | 一篇高质量小红书笔记需要20-40分钟撰写 | 产量受限，人力成本高 |
| **质量参差不齐** | 内容质量依赖个人能力，缺乏标准化评审机制 | 爆款率低，品牌形象不统一 |
| **排版适配繁琐** | 同一主题需为不同平台（小红书/抖音/公众号）分别调整格式和风格 | 重复劳动，效率低下 |
| **工具碎片化** | 选题用一个工具，写作用另一个，发布又用另一个 | 工作流割裂，上下文丢失 |

### 1.3 市场机会

- 自媒体运营AI工具市场**尚无端到端的中文解决方案**（详见《竞品分析》）
- 大语言模型（LLM）技术成熟，多Agent协作框架（LangGraph）可支撑复杂工作流
- 国产开源模型（DeepSeek）性能达到实用水平，成本大幅下降

## 2. 产品概述

### 2.1 产品定义

**自媒体智能运营Agent系统**是一个基于多Agent架构的AI内容运营平台，通过将自媒体运营流程拆解为选题→创作→审核→适配四个环节，由专业化Agent协作完成，实现内容运营全流程自动化。

### 2.2 产品愿景

> 让每一个自媒体运营者拥有AI驱动的内容团队。

### 2.3 目标用户

| 用户画像 | 描述 | 核心需求 |
|----------|------|----------|
| **中小企业自媒体运营** | 1-3人团队，负责公司多平台内容运营 | 提效降本，提升内容质量和产量 |
| **个人内容创作者** | 自媒体博主、KOL、独立创作者 | 快速找选题，高质量出稿 |
| **MCN机构运营** | 管理多个账号的内容团队 | 标准化流程，批量生产 |
| **自由职业者** | 为客户代运营自媒体的freelancer | 多风格切换，高效交付 |

**核心用户（MVP阶段）**：中小企业自媒体运营人员 + 个人内容创作者

## 3. 核心功能设计

### 3.1 功能全景

```
┌─────────────────────────────────────────────────────────────┐
│                    自媒体智能运营Agent系统                     │
├─────────────┬───────────────┬──────────────┬────────────────┤
│  热点选题     │   内容生成     │  内容审核     │  多平台适配     │
│  推荐Agent   │    Agent      │   Agent      │    Agent       │
├─────────────┼───────────────┼──────────────┼────────────────┤
│ · 热点搜索   │ · 小红书文案   │ · 多维评分    │ · 小红书适配    │
│ · 趋势分析   │ · 抖音脚本    │ · 改进建议    │ · 抖音适配     │
│ · 选题推荐   │ · 公众号文章   │ · 迭代优化    │ · 公众号适配    │
│ · 角度挖掘   │ · 风格定制    │ · 合规检查    │ · 格式转换     │
└─────────────┴───────────────┴──────────────┴────────────────┘
```

### 3.2 热点选题推荐Agent

**功能描述**：自动搜索互联网热点信息，分析趋势，结合目标平台特点，推荐5个优质选题。

| 要素 | 详情 |
|------|------|
| **输入** | 用户指定的领域/关键词（如"美妆"、"科技数码"） |
| **处理流程** | 1. 调用DuckDuckGo搜索最新热点 → 2. 分析搜索结果提取趋势 → 3. 结合平台特点生成选题 |
| **输出** | 5个推荐选题，每个包含：标题建议、选题理由、热度评分(1-10)、适合平台、建议角度 |
| **工具依赖** | DuckDuckGo Search API |

**输出示例**：
```json
{
  "topics": [
    {
      "title": "2026春季必入的5款平价防晒测评",
      "reason": "防晒话题进入季节高峰期，'平价'关键词搜索量周环比上升45%",
      "heat_score": 9,
      "platforms": ["小红书", "抖音"],
      "angle": "以实测数据对比为核心卖点，突出性价比"
    }
  ]
}
```

### 3.3 内容生成Agent

**功能描述**：根据选定的话题，按照目标平台的内容风格和规则，生成高质量的原创内容。

| 要素 | 详情 |
|------|------|
| **输入** | 选定的话题、目标平台、内容风格偏好 |
| **处理流程** | 1. 从知识库检索同类型优秀样本 → 2. 分析样本的结构和风格 → 3. 生成符合平台规范的内容 |
| **输出** | 完整的平台内容，包含标题、正文、标签/话题 |
| **工具依赖** | ChromaDB向量检索（样本库） |

**平台内容规范**：

| 平台 | 标题要求 | 正文要求 | 标签要求 |
|------|----------|----------|----------|
| 小红书 | 20字内，含emoji，抓眼球 | 500-800字，分段清晰，emoji点缀 | 5-8个，含热门话题标签 |
| 抖音 | 简短有力，15字内 | 视频脚本格式，口播+画面提示 | 3-5个，含挑战赛标签 |
| 公众号 | 25字内，引发好奇 | 1500-2500字，深度分析 | 文末标签，2-3个 |

### 3.4 内容审核Agent

**功能描述**：对生成的内容进行多维度质量评审，给出量化评分和改进建议。

| 要素 | 详情 |
|------|------|
| **输入** | 生成的内容、目标平台 |
| **处理流程** | 1. 从三个维度独立评分 → 2. 计算综合分 → 3. 低于阈值则给出具体改进建议 |
| **输出** | 三维度评分（各1-10）、总分、通过/不通过判定、改进建议列表 |

**评分维度**：

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| **吸引力** | 40% | 标题是否抓眼球、开头是否有hook、整体是否引发阅读欲望 |
| **准确性** | 30% | 信息是否准确、逻辑是否通顺、是否有事实错误 |
| **平台适配度** | 30% | 是否符合目标平台的内容格式、风格、字数要求 |

**审核规则**：
- 总分 ≥ 21分（满分30）：通过，输出最终内容
- 总分 < 21分：不通过，生成改进建议，返回Writer Agent重写
- 最多迭代3轮，超过3轮仍未达标则输出当前最佳版本并标注警告

### 3.5 多平台适配Agent

**功能描述**：将审核通过的内容适配到不同平台的格式和风格要求。

| 要素 | 详情 |
|------|------|
| **输入** | 审核通过的内容、目标适配平台列表 |
| **处理流程** | 1. 分析原始内容核心信息 → 2. 按目标平台规则调整格式/风格/长度 → 3. 输出各平台版本 |
| **输出** | 各平台适配版本的内容 |

**适配规则**：

| 转换方向 | 调整要点 |
|----------|----------|
| 小红书 → 抖音 | 缩短文案、增加口语化表达、添加视频脚本提示 |
| 小红书 → 公众号 | 扩充深度内容、增加数据/案例、调整为长文格式 |
| 抖音 → 小红书 | 从脚本提取核心观点、补充图文细节、增加emoji |

## 4. 技术架构

### 4.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                   Streamlit Frontend                     │
│         用户界面 · 参数配置 · 结果展示 · 交互控制          │
└────────────────────────┬────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────┐
│                   LangGraph Orchestrator                  │
│              状态管理 · 流程编排 · 条件路由                 │
├──────────┬───────────┬──────────────┬───────────────────┤
│ Research │  Writer   │  Reviewer    │    Adapter        │
│  Agent   │  Agent    │  Agent       │    Agent          │
└────┬─────┴─────┬─────┴──────┬───────┴─────┬─────────────┘
     │           │            │             │
┌────▼────┐ ┌───▼─────┐ ┌───▼──────┐ ┌───▼──────┐
│DuckDuck │ │ChromaDB │ │  评分引擎  │ │ 平台规则库│
│Go Search│ │ 样本库  │ │          │ │          │
└─────────┘ └─────────┘ └──────────┘ └──────────┘
                 │
          ┌──────▼──────┐
          │  DeepSeek    │
          │  API / 本地  │
          └─────────────┘
```

### 4.2 技术选型

| 层级 | 技术选型 | 选型理由 |
|------|----------|----------|
| **LLM** | DeepSeek API | 中文能力强，性价比高，支持本地部署 |
| **Agent框架** | LangChain + LangGraph | 成熟的多Agent编排框架，支持状态机 |
| **搜索工具** | DuckDuckGo Search | 免费、无需API Key、结果质量可接受 |
| **向量数据库** | ChromaDB | 轻量级、易部署、适合MVP阶段 |
| **前端** | Streamlit | 快速原型、Python原生、组件丰富 |
| **语言** | Python 3.11+ | AI/ML生态成熟，LangChain原生支持 |

### 4.3 数据流设计

```
用户输入领域关键词
       │
       ▼
[Research Agent] ──搜索热点──→ 返回5个选题
       │
       ▼
用户选择/确认选题
       │
       ▼
[Writer Agent] ──检索样本──→ 生成平台内容
       │
       ▼
[Reviewer Agent] ──多维评分──→ 评分 ≥ 21? ──否──→ 返回Writer重写（最多3轮）
       │是
       ▼
[Adapter Agent] ──平台适配──→ 输出各平台版本
       │
       ▼
用户确认/微调/导出
```

## 5. MVP范围定义

### 5.1 MVP功能范围

| 功能 | 是否MVP | 备注 |
|------|---------|------|
| 热点选题推荐 | ✅ 是 | 核心流程入口 |
| 小红书内容生成 | ✅ 是 | 先做最热门的平台 |
| 内容质量审核 | ✅ 是 | 核心差异化功能 |
| 审核-重写迭代 | ✅ 是 | 保证质量闭环 |
| 抖音内容适配 | ❌ V2 | MVP后优先迭代 |
| 公众号内容适配 | ❌ V2 | MVP后优先迭代 |
| 样本知识库管理 | ❌ V2 | MVP使用预置样本 |
| 批量生成 | ❌ V3 | 后续高级功能 |
| 定时任务 | ❌ V3 | 后续高级功能 |

### 5.2 MVP用户流程

```
Step 1: 用户输入感兴趣的领域（如"美妆护肤"）
            │
Step 2: 系统展示5个推荐选题（含热度评分和理由）
            │
Step 3: 用户选择一个选题
            │
Step 4: 系统自动生成小红书风格内容
            │
Step 5: 系统自动审核，展示评分和改进建议
            │  （若未达标，自动重写并重新审核，最多3轮）
            │
Step 6: 展示最终内容，用户可复制/导出
```

## 6. 非功能性需求

### 6.1 性能需求

| 指标 | 目标值 | 备注 |
|------|--------|------|
| 选题推荐响应时间 | < 15秒 | 含搜索+分析 |
| 内容生成响应时间 | < 30秒 | 含样本检索+生成 |
| 内容审核响应时间 | < 10秒 | 纯LLM评估 |
| 全流程端到端时间 | < 2分钟 | 含一轮迭代 |

### 6.2 质量指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|----------|
| 内容质量评分 | 平均 > 8/10 | Reviewer Agent评分 |
| 一次通过率 | > 60% | 首次生成即通过审核的比例 |
| 用户满意度 | > 4/5 | 用户反馈评分 |
| 内容原创度 | > 95% | 查重工具检测 |

### 6.3 安全需求

- 用户数据本地存储，不上传至第三方
- API Key等敏感信息通过环境变量管理
- 内容审核包含合规检查（敏感词过滤）

## 9. 风险评估

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|----------|
