# 项目2 图片增强收口总结 v1

最后更新：2026-04-11

## 1. 这轮实际补了什么

这一轮把图片能力从“单图可生成”继续补到了“更接近原始规划”的状态，重点有 4 项：

1. 多图候选主链路  
- 已支持 `cover_candidate_count=1-4`
- 候选图会进入状态、导出包和前端展示
- 第一张图自动作为主图

2. 请求级真实配图切换  
- 服务默认仍可保持 `IMAGE_MOCK=true`
- 但单次请求可通过 `image_mock=false` 走真实图片模型
- 这次还顺手修掉了“默认 mock 时真实图片 client 不初始化”的 bug

3. 图片质量校验  
- 已校验文件存在、文件大小、mime type、尺寸、宽高比、请求尺寸匹配
- 当前对真实多图结果已通过

4. 图片并发对比  
- 已有串行 vs 并发的真实 compare 报告
- 当前可以支撑“图片并发优化”这一类工程化表达

5. 图文一致性轻量检查
- 已新增不依赖额外视觉模型的启发式一致性检查
- 依据标题、正文、标签与 `image_plan / image_asset` 文本重合度生成 `status / score / matched_keywords / missing_keywords / note`
- 结果已接入状态、导出包、质量校验与 demo 展示

## 4. 这轮修掉的关键 bug

### bug 1：请求级 `image_mock=false` 失效

原因：
- 服务初始化时，如果全局 `IMAGE_MOCK=true`，就不会创建真实图片 client
- 导致单次请求即使传 `image_mock=false`，也还是走 mock

修复：
- 真实图片 client 不再被全局 mock 阻断初始化
- 是否走 mock 改成在节点执行时再判断

影响：
- `/demo` 里的“真实配图”切换现在才真正生效
- `/v2/run` 和 `/v2/run/stream` 的请求级覆写也真正生效

### bug 2：同步运行接口缺少顶层 `status`

修复：
- `run_workflow` 返回值已补顶层 `status`

影响：
- 前端同步运行和后续自动化验证更稳定
