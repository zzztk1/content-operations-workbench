# 项目2阶段0：竞品分析与方案取舍

最后更新：2026-04-09

## 1. 这一步要解决什么问题

竞品分析在这个项目里，不是为了证明“市面上没人做”，而是为了回答两个更重要的问题：

1. 为什么这个项目值得自己做，而不是直接买一个成熟产品
2. 为什么最终方案要选择“自研工作流系统”，而不是直接用平台型方案搭出来

## 2. 先解释几个常见词

- `SaaS`（Software as a Service，软件即服务）：直接买来用的在线软件产品。
- `Agent`（智能体）：能基于目标自动调用模型和工具完成任务的系统角色。
- `Workflow`（工作流）：把一件事拆成多个步骤，并定义它们的流转关系。
- `RAG`（Retrieval-Augmented Generation，检索增强生成）：先检索资料，再让模型生成结果。
- `Brand Voice`（品牌语气）：让内容风格保持统一的一套规则和资产。

## 3. 竞品与替代方案怎么分

项目2面对的替代方案，其实主要是 3 类：

### 3.1 成熟内容生产产品

代表方向：

- Jasper
- Copy.ai
- Notion AI

这类产品的特点是：

- 上手快
- 模板多
- 更适合直接产出营销内容
- 强调内容生成效率和品牌语气统一

### 3.2 平台型 Agent / Workflow 产品

代表方向：

- Coze
- Dify
- Zapier Agents

这类产品的特点是：

- 更强调工作流编排和工具连接
- 适合快速做原型
- 对非研发用户更友好

### 3.3 自研工程方案

代表方向：

- `LangGraph StateGraph`
- `PostgreSQL Checkpointer`
- `SSE`
- `SlowAPI`

这类方案的特点是：

- 需要自己设计和维护
- 成本更高
- 但可控性、可恢复性、可观测性更强

## 4. 逐类分析

## 4.1 成熟内容产品为什么不能直接替代这个项目

### 优势

- 生成内容很快
- 很适合直接交付给运营使用
- 界面和模板通常比较成熟
- 在 `Brand Voice`（品牌语气统一）这类场景有明显优势

### 不足

- 更像“内容生产工具”，不是“内容工作流系统”
- 很难把研究、审核、审批、回查、恢复这些流程能力做成你自己的系统资产
- 流程状态和底层运行逻辑通常不可控
- 对“节点级指标、事件流、持久化恢复”这类工程能力支撑不足

### 对项目2的判断

如果目标只是让团队更快写文案，成熟产品完全有价值。  
但如果目标是做一套：

- 可审批
- 可恢复
- 可回查
- 可测量
- 可扩展

的内容工作流系统，它们就不是最终替代方案。

## 4.2 平台型方案为什么不能作为最终形态

### 优势

- `Workflow`（工作流）搭建速度快
- 容易接知识库和外部工具
- 非常适合快速验证产品逻辑
- 对 Demo 和原型阶段很友好

### 不足

- 平台能力不等于自己的系统能力
- 在状态恢复、持久化语义、流式事件、限流、健康检查等方面，往往受平台边界限制
- 当项目目标要求你讲清楚底层架构时，平台方案的说服力会弱一些

### 对项目2的判断

如果目标是 1 天搭出一个可演示原型，平台型方案是好选择。  
但如果目标是做一套真正的工程化内容工作流系统，平台更适合：

- 前期验证思路
- 参考交互方式
- 作为替代方案对比

而不适合作为最终落地形态。

## 4.3 为什么项目2最终选择自研

项目2要做的不是“让模型写篇文案”，而是要把下面这些能力组合起来：

- 研究选题
- 内容生成
- 结构化审核
- 审批分支
- 导出内容包
- run 回查
- 状态恢复
- 流式展示
- 健康检查与限流

只有当这套系统是自研时，你才能真正掌握：

- 节点怎么拆
- 状态怎么设计
- `StateGraph` 怎么编排
- `Checkpointer` 怎么恢复
- 事件流怎么发
- 指标怎么测

所以项目2最终路线选择自研，不是因为“平台不好”，而是因为这个项目的目标本身更偏工程化系统，而不是内容工具使用。

## 5. 方案对比表

| 方案 | 优势 | 劣势 | 对项目2的结论 |
|---|---|---|---|
| 成熟内容产品 | 快速产出内容、模板成熟、上手快 | 工作流不可控、状态和恢复能力弱、难沉淀系统资产 | 可参考，不作为最终方案 |
| 平台型工作流产品 | 原型快、接工具方便、低代码友好 | 底层可控性弱、工程表达有限、受平台边界限制 | 可做参考或原型，不作为最终方案 |
| 自研工程方案 | 可控、可恢复、可观测、可测量、可扩展 | 成本更高、实现更复杂 | 这是项目2最终方案 |

## 6. 竞品分析后的产品决策

### 6.1 我们不做什么

- 不做单点写作工具
- 不做只会生成内容、不会管理流程的产品
- 不做完全依赖外部平台边界的系统

### 6.2 我们要做什么

做一套面向内容运营场景的工作流系统：

- 以大模型提供智能能力
- 以工作流提供流程控制
- 以状态持久化提供恢复和回查
- 以事件流和指标提供可观测与可测量能力

## 7. 本阶段验收标准

- 你能说清楚为什么成熟产品不能完全替代这个项目。
- 你能说清楚为什么 Coze / Dify 适合原型，但不作为最终形态。
- 你能说清楚项目2最终做的是“系统”，不是“工具使用”。
