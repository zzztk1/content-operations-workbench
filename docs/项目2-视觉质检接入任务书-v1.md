# 项目2 视觉质检接入任务书 v1

最后更新：2026-04-11

## 1. 目标

把项目2当前的“启发式图文一致性检查”升级为“视觉模型级质检”。

本轮只做一件事：
在现有图片主链路后新增一个视觉质检节点，让系统真正具备“看图判图”的能力。

推荐模型：
- 视觉质检模型：`step-1o-turbo-vision`
- 文本主模型：保持 `step-3.5-flash`
- 图片生成模型：保持 `step-2x-large`

## 2. 当前现状

已完成（含本轮视觉质检交付）：
- `visual_subgraph`
- `plan_cover -> generate_cover`
- 真实图片 API（默认模型基线 `step-2x-large`）
- 多候选图
- 图片质量校验
- 图文一致性启发式检查
- `review_cover_visual` 与 StepFun 视觉模型（默认 `step-1o-turbo-vision`）、`VISION_REVIEW_MOCK` / 请求级覆盖
- 视觉质检结构化输出已进入 state、导出包与 `/demo`
- mock / real / badcase 报告：`benchmarks/latest_visual_review_*_report.json`（见 `docs/项目2-视觉质检收口总结-v1.md`）

仍可作为后续产品化项（不在本轮任务书“缺口”里按未完成表述）：
- 更高成本的端到端准确率评测与自动修复闭环

## 3. 本轮必须完成的功能

### 3.1 新增视觉质检节点

在图片生成后新增：
- `review_cover_visual`

建议链路：
- `plan_cover -> generate_cover -> review_cover_visual`

### 3.2 新增视觉模型配置

新增环境变量：
- `STEPFUN_VISION_API_KEY`
- `STEPFUN_VISION_API_BASE`
- `STEPFUN_VISION_MODEL`
- `VISION_REVIEW_MOCK`

默认建议：
- `STEPFUN_VISION_API_KEY` 回退到 `STEPFUN_API_KEY`
- `STEPFUN_VISION_API_BASE=https://api.stepfun.com/v1`
- `STEPFUN_VISION_MODEL=step-1o-turbo-vision`
- `VISION_REVIEW_MOCK=true`

### 3.3 视觉质检输出 schema

至少输出这些字段：

```json
{
  "theme_match_score": 0,
  "readability_score": 0,
  "composition_score": 0,
  "overall_score": 0,
  "passed": false,
  "risk_flags": [],
  "feedback": ""
}
```

### 3.4 接入 state / export / demo

必须把视觉质检结果接入：
- state
- export JSON / Markdown
- `/demo`

### 3.5 mock 与真实双模式

必须支持：
- `VISION_REVIEW_MOCK=true` 时本地低成本调试
- 可通过请求级或运行时开关切到真实视觉质检

## 4. 推荐实现路线

### 4.1 节点输入

`review_cover_visual` 的输入建议包含：
- `brief`
- `draft.title`
- 正文摘要
- `tags`
- `image_plan`
- `image_asset.image_url` 或本地图片转 base64

### 4.2 节点职责

只做三件事：
- 判断主题一致性
- 判断封面可读性
- 判断异常风险

不要在这一轮加入复杂 rerank、多图自动重选、二次编辑。

### 4.3 成本控制

优先只对最终主图调用一次视觉质检。

不要在这一轮对所有候选图都做真实视觉质检，除非 mock 模式。

## 5. 验收指标

### 必须通过

1. `review_cover_visual` 出现在 trace 中
2. mock 视觉质检验证通过
3. 至少一次真实视觉质检验证通过
4. 导出 JSON 里有视觉质检字段
5. `/demo` 能展示视觉质检结果

### 结果文件

至少生成：
- `benchmarks/latest_visual_review_mock_report.json`
- `benchmarks/latest_visual_review_real_report.json`

如顺手补 badcase，再加：
- `benchmarks/latest_visual_review_badcase_report.json`

## 6. 评分、badcase 与评测要求

### 6.1 视觉质检评分

本轮必须输出可解释的分项分数：
- `theme_match_score`
- `readability_score`
- `composition_score`
- `overall_score`

并明确：
- `passed`
- `risk_flags`
- `feedback`

### 6.2 badcase

至少要补一组 badcase 验证，覆盖其中两类以上：
- 明显偏题的封面图
- 标题区域不适合封面展示的图
- 构图混乱或信息重心不明确的图

允许先用 mock / fixture / 人工构造 badcase，不要求这一轮大规模真实烧图。

### 6.3 评测结果文件

本轮目标结果文件：
- `benchmarks/latest_visual_review_mock_report.json`
- `benchmarks/latest_visual_review_real_report.json`
- `benchmarks/latest_visual_review_badcase_report.json`

### 6.4 后续可继续调优项

如果实现过程中顺手暴露出低风险优化点，可以一并补：
- 视觉质检提示词收敛
- 评分阈值调整
- demo 中视觉质检展示更清晰
- 导出结果里补更清楚的视觉质检摘要

1. 先补代码与 schema

4. 最后同步文档与简历边界

- 只做最小一次真实视觉质检验证
- 不要破坏现有文本主链路和图片生成主链路

1. 改了哪些文件
2. 跑了哪些验证
3. 哪些通过
