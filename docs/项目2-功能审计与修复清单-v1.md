## 4. 这轮修复了什么

### 4.1 Step Plan 线路问题

- 已确认问题不在 API key，而在于早期误走了普通按量接口
- 默认配置已切回：
  - `STEPFUN_API_BASE=https://api.stepfun.com/step_plan/v1`
  - `STEPFUN_MODEL=step-3.5-flash`

### 4.2 Step Plan 结构化输出不稳定

- 已修复：
  - `Step Plan` 路线不再硬卡 `max_tokens`
  - 不再强依赖 `JSON Mode`
  - 解析器补了 fenced JSON salvage
- 当前真实链路已稳定到 `direct / fenced-salvage`

### 4.3 Windows 控制台编码导致 benchmark 报错

- 已修复所有 benchmark 脚本的 UTF-8 stdout 输出
- `validate_step_plan_runtime.py` 不再因 emoji 输出报 `UnicodeEncodeError`

### 4.4 request_id 与结构化日志证据不足

- 已补 API 级 JSON 日志
- 已补 engine 级 JSON 日志
- 已补 `request_id` 串联
- 导出包已补 `request_id / graph_version / metrics_summary`

### 4.5 缺少统一功能审计结果

- 已新增：
  - `benchmarks/audit_feature_coverage.py`
  - `benchmarks/latest_feature_audit_report.json`

### 4.6 token 级 streaming 真正补齐

- 已修复：
  - `LangGraph` 流式接口不再只发图级 update
  - `Step Plan` 真实流现在会透传 token 级增量片段
  - `validate_step_plan_runtime.py` 已开始校验 `token_event_count / token_summary_event_count / TTFT`
- 当前结果：
  - `benchmarks/latest_step_plan_runtime_report.json`
  - `token_event_count > 0`
  - `TTFT` 已捕获

### 4.7 LangSmith 真实验证补齐

- 已完成：
  - `LANGSMITH_API_KEY` 真实接入
  - tracing 接入点、项目名、endpoint、v2 tracing 开关全部补齐
  - 新增 `benchmarks/validate_langsmith_runtime.py`
  - 已用新的 key 完成真实 LangSmith 远端 tracing 验证
  - `latest_langsmith_runtime_report.json` 中已出现 `matched_runs`
