# 项目2-Gemini前端重构提示词-v2

你现在是“项目2前端重构设计与实现顾问”。

我有一个已经跑通后端能力的 AI 内容工作流项目，需要你**只聚焦前端页面重构与前后端展示适配**。请不要改动业务后端架构，不要重写接口协议，不要把它做成聊天机器人页面。

## 一、项目定位

这是一个“智能内容运营系统”，不是普通对话助手。

它的核心是一个内容工作流：

- brief intake
- research
- writer
- review
- cover planning
- cover generation
- visual review
- export

系统支持：

- 文本生成
- 封面图生成
- 多候选图
- 视觉质检
- 流式事件
- 引导模式与自动模式
- PostgreSQL 状态回查

所以页面定位应该是：

> 一个 AI 内容工作流操作台 / Run 驾驶舱

而不是：

> 一个聊天框

## 二、当前前后端已对齐、不要推翻的接口

后端接口已经基本定了，前端必须基于这些接口设计，不要自创协议。

### 1. 健康检查

- `GET /health`

用途：
- 展示服务状态
- 展示文本模型 / 图片模型 / 视觉模型
- 展示 PostgreSQL 连通
- 展示 mock / real 状态

### 2. 能力说明

- `GET /v2/workflow-capabilities`

用途：
- 获取 run_mode 支持情况
- 获取 export_formats 支持情况
- 获取 endpoint 能力说明

### 3. 同步运行

- `POST /v2/run`

请求字段核心包括：
- `brief`
- `platform`
- `style`
- `run_mode`
- `export_formats`
- `reviewer_threshold`
- `max_revisions`
- `approval_decision`
- `approval_note`
- `image_mock`
- `cover_candidate_count`
- `vision_review_mock`

### 4. 流式运行

- `POST /v2/run/stream`

用途：
- 通过 SSE 接收：
  - `start`
  - `token`
  - `token_summary`
  - `update`
  - `final`
  - `error`

### 5. 引导模式继续运行

- `POST /v2/run/continue`

用途：
- 在 guided 模式下，research 阶段先停住
- 用户选择候选选题后继续跑完整链路

### 6. 单次运行回查

- `GET /v2/runs/{run_id}`

用途：
- 回查 state
- 拿 guided 模式的候选选题
- 查看最终结果

## 三、当前前端存在的真实问题

你设计和实现时，必须优先解决这些问题：

### 1. 页面语义错位

当前页面有时更像“接口测试台”或“拼装面板”，没有体现“工作流系统”的产品感。

### 2. 正文展示优先级不对

当前结果预览里，图片和卡片容易抢占视觉中心，正文容易不稳定或不明显。

前端必须做到：
- 标题稳定显示
- 正文稳定显示
- 标签稳定显示
- 不允许“只有标题没有正文”的预览体验

### 3. 图片和正文关系没有处理好

当前页面里，主图、候选图、正文的层级关系还不够合理。

需要做到：
- 正文是交付物核心
- 图片是封面辅助结果
- 不能让图片把正文存在感压没

### 4. 引导模式体验不够产品化

guided 模式虽然接口通了，但需要更清晰的：
- 候选选题区
- 继续运行按钮
- 当前处于“等待选题”的状态说明

### 5. mock / real 状态不够清晰

页面必须明确显示：
- 当前是否真实配图
- 当前是否真实视觉质检
- 如果是 mock，要醒目提示

### 6. 当前中文文案和编码体验不够稳定

页面最终必须是正常中文界面，不允许乱码风格文案。

你需要同时兼顾：

- 前后端真实适配
- 工作流语义

## 五、设计方向要求

### 1. 页面风格

请参考“商业化 AI 工作流产品后台 / 运营工作台”的感觉，而不是聊天机器人。

可以参考的页面气质：
- 任务工作台
- Run 驾驶舱
- 内容生产控制台

### 2. 结构建议

我希望页面至少分成这几个区域：

#### A. 左侧：任务配置区

包含：
- brief
- platform
- style
- run_mode
- export_formats
- reviewer_threshold
- max_revisions
- approval_decision
- approval_note
- image_mock / real
- cover_candidate_count
- vision_review_mock / real

#### B. 中间：交付预览区

重点展示：
- 标题
- 正文
- 标签
- 主图
- 候选图
- 视觉质检摘要
- 图文一致性摘要

要求：
- 正文优先级高于图片
- 主图是辅助，不是压倒正文的主视觉

#### C. 右侧：流程追踪区

展示：
- 当前状态
- run_id
- request_id
- TTFT
- 已完成节点
- 当前阶段

#### D. 二级区域：开发者抽屉 / 原始事件

展示：
- raw events
- metrics json
- health snapshot

但不要抢首屏。

### 3. 引导模式体验

guided 模式下必须有独立候选选题选择区，体验要像“流程决策点”，不能像一串普通 radio。

### 4. 图片展示体验

必须解决：
- 主图展示
- 候选图展示
- mock 强提示
- 视觉质检结果展示
- 不让图片盖过正文

### 5. 文案要求

页面中文文案必须正常、简洁、产品化。

不要出现：
- 乱码
- 技术人自嗨文案
- 过于啰嗦的调试提示堆满页面
