# 工作流验证与演示手册

最后更新：2026-04-11

## 1. 验证目标

这份手册用于验证项目2当前最重要的 5 类能力：

1. 旧版 baseline 是否还稳定。
2. LangGraph v2 在 mock 模式下是否稳定。
3. `Step Plan + PostgreSQL` 真实链路是否可跑。
4. API 治理能力是否真的可用。
5. 封面配图与视觉质检（图片默认 `step-2x-large`，视觉质检默认 `step-1o-turbo-vision`，见 `VISION_REVIEW_MOCK`）。

### 2.5 跑功能审计

```bash

```

期望结果：

- 生成 `benchmarks/latest_feature_audit_report.json`，含 `image_artifacts` 与扩展后的 `feature_matrix`

### 2.6 跑视觉质检专项（mock / real / badcase）

- mock（全链路 mock，含视觉）：`py benchmarks\validate_visual_review_mock.py` → `benchmarks/latest_visual_review_mock_report.json`
- real（低成本：复用 `outputs/images` 下已有 PNG，调用一次视觉模型；需 `STEPFUN_VISION_API_KEY` 或未单独配置时可用的 `STEPFUN_API_KEY`）：`py benchmarks\validate_visual_review_real.py` → `benchmarks/latest_visual_review_real_report.json`
- badcase（结构化 badcase fixture）：`py benchmarks\validate_visual_review_badcase.py` → `benchmarks/latest_visual_review_badcase_report.json`

口径与字段说明见：`docs/项目2-视觉质检收口总结-v1.md`。

## 3. API 演示入口

### 3.1 启动服务

```bash
cd F:\codex\codex1\projects\media-agent\src
py -m uvicorn api_v2:app --host 127.0.0.1 --port 8000
```

### 3.2 健康检查

```bash
curl http://127.0.0.1:8000/health
```

重点看：

- `llm_provider_route`
- `llm_api_base`
- `postgres_connectivity`
- `llm_circuit_breaker`
- `langsmith_tracing`
- `image_model`、`checks.image_configured`
- `vision_model`、`vision_review_mock`、`vision_client_available`、`checks.vision_configured`

### 3.3 运行一次 workflow

```bash
curl -X POST http://127.0.0.1:8000/v2/run ^
  -H "Content-Type: application/json" ^
  -H "X-Request-ID: pm-demo-001" ^
  -d "{\"brief\":\"AI Agent 在内容运营中的真实应用场景\",\"platform\":\"小红书\",\"style\":\"种草推荐\"}"
```

### 3.4 演示事件流

```bash
curl -N -X POST http://127.0.0.1:8000/v2/run/stream ^
  -H "Content-Type: application/json" ^
  -H "X-Request-ID: pm-stream-001" ^
  -d "{\"brief\":\"AI Agent 在内容运营中的真实应用场景\",\"platform\":\"小红书\",\"style\":\"种草推荐\"}"
```

当前事件流能力：

- 已完成 token 级 `SSE` 事件流
- 当前流中已经能看到 `start / token / update / final`
- `TTFT`（首字延迟）已经进入运行报告

## 4. 推荐演示口径

> 先跑 v2 mock 验证，证明图结构稳定；再跑 Step Plan 真实链路，证明真实模型和 PostgreSQL 都打通；最后演示 `/health` 和 `/v2/run/stream`，展示服务治理、token 级事件流和 `TTFT` 捕获能力。
