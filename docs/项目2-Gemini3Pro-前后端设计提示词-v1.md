# 项目2 Gemini 3 Pro 前后端设计提示词

这份文档不是给最终用户看的，而是给“项目2主线程 / 项目2前后端适配线程”使用的。

目标：
- 在**可核验**前提下，尽可能使用 Cursor 中的 Gemini 设计模型完成页面方案
- 如果本机 Cursor Agent 当前**不支持 Gemini**，就不能伪造“Gemini 已调用”的结论
- 让页面设计任务和当前真实代码、API、工作流能力做适配

---

## 一、对子线程的强制要求

你现在是“项目2主线程”或“项目2前后端适配工作线程”。

这一轮涉及前端 / 后台页面设计时，必须先做“模型可用性核验”，然后再决定是否真的调用 Gemini。

### 第一步：先核验

你必须先核验当前 Cursor Agent 是否真的支持 Gemini 模型：

1. 运行或检查：
   - `agent --list-models`
2. 把结果写入文档
3. 只有当模型列表里**明确出现 Gemini 3.x / Gemini Pro** 时，才允许继续声称“本轮使用 Gemini 设计”

### 第二步：根据核验结果分支执行

#### 情况A：Gemini 在模型列表中

则：
- 必须实际调用 Cursor 里的 Gemini 模型
- 至少调用两次：
  - 一次做前台工作台设计
  - 一次做后台管理设计
- 必须保留：
  - `meta.json`
  - `task.txt`
  - `result.txt`
  - 模型列表快照

#### 情况B：Gemini 不在模型列表中

则：
- **不能再宣称“已调用 Gemini”**
- 你有两个选择：
  1. 使用当前 Cursor Agent 支持的模型完成设计，并明确写“非 Gemini”
  2. 暂停该部分，等待主线程决定是否改用 Gemini 官方 API 或人工在 Cursor UI 中调用

无论如何：
- 不允许伪造“Gemini 已实际调用”的口径

## 二、必须遵守的事实约束

1. 不允许你自己直接脑补完整设计稿
   - 你可以先做产品定义、接口审计、页面功能拆解
   - 但页面设计本身应由外部设计模型或用户指定方式完成

2. 如果没有通过可核验方式实际调用 Gemini，就不能写：
   - “已调用 Gemini 3.1 Pro”
   - “Gemini 设计已完成”

3. 外部设计结果回来后，必须继续做这三件事：
   - 把设计结果和当前真实 API / 数据结构对齐
   - 标出哪些能直接实现，哪些需要后端补接口
   - 形成“设计稿 -> 页面 -> 接口 -> 状态流”的适配文档

4. 如果设计方案和当前真实项目冲突：
   - 不能直接照搬
   - 要做二次收口
   - 保证最终落地的是“适配项目真实能力”的方案

## 四、前台设计提示词模板

如果模型核验通过，可以把下面这段发给设计模型：

```text
请为一个“自媒体智能内容运营系统”设计用户侧前端页面方案。

这是一个 AI 内容运营工作台，不是普通聊天机器人，也不是传统管理后台。它的目标是帮助内容运营人员完成从 brief 输入、选题研究、内容写作、审核修改到最终导出的完整流程。

请基于以下真实产品要求设计：

一、产品定位
- 面向自媒体运营人员、内容创作者、小团队使用
- 强调“流程可视化、人工可控、内容可复用”
- 前端主要负责功能使用和结果展示
- 数据监控、日志采集、系统健康等复杂技术能力主要由后端承接，前端只保留轻量入口

二、核心使用模式
1. 自动模式
- 用户输入 brief 后，一键自动生成
- 系统自动完成研究、写作、审核、导出

2. 引导模式
- 用户输入 brief 后，系统先执行“选题研究”
- 前端需要展示多条候选选题
- 每条选题展示：
  - 选题标题
  - 推荐理由
  - 热度级别
  - 面向人群
  - 内容角度
- 用户选择其中一个选题后，才继续进入后续写作、审核和导出
- 还要支持“重新生成选题”

三、前端需要体现的主要功能
1. 新建任务
2. 研究阶段
3. 内容生成流程页
4. 审核页
5. 内容结果页
6. 导出模块
7. 历史记录页
8. 系统状态入口

四、设计要求
- 页面文案尽量中文化
- 少用专业英文术语
- 不要做成聊天页
- 不要做成传统 admin 模板
- 要更像“内容运营工作台”
- 要有 AI 过程感、步骤感、卡片感、可控感

五、请输出内容
1. 页面信息架构
2. 主要页面布局说明
3. 关键组件清单
4. 核心交互流程
5. 任务执行页的详细布局
6. 候选选题选择页的详细布局
7. 内容结果页和导出模块的详细布局
8. 整体视觉风格建议
9. 如合适，给出 React / Next.js 组件拆分建议
```

   - 哪些页面只是视觉预留
