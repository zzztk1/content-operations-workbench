## 二、产品和交互的锁定要求

你必须按以下要求推进，不允许偏离：

### 1. 前后端分工
- 前端负责：
  - 新建任务
  - 选择模式
  - 查看研究阶段候选选题并手动选择
  - 查看流程执行状态
  - 审核与修改
  - 查看最终结果
  - 多格式导出
- 后端负责：
  - 任务调度
  - 状态持久化
  - 指标采集
  - 日志
  - 健康检查
  - mock / 限流 / 熔断 / 系统状态
- 前端不要铺太多技术监控细节，只保留“后台入口 / 系统状态入口”

### 2. 必须支持两条用户路径
- 自动模式：
  - 用户输入 brief 后，一键从研究到导出全部自动完成
- 引导模式：
  - 用户输入 brief 后，系统先只执行研究阶段
  - 前端必须展示多个候选选题
  - 用户选定一个选题后，再继续进入写作、审核、导出

### 3. 研究阶段必须支持人工选题
- 后端不能再默认永远自动选第一个 topic
- 需要有“研究完成 -> 等待选题 -> 用户确认 -> 继续执行”的路径
- 前端要能清晰展示：
  - 选题标题
  - 推荐理由
  - 热度级别
  - 面向人群
  - 内容角度

### 4. 导出必须做前后端适配
- 前端要有“导出格式选择器”
- 后端要明确哪些格式真实支持，哪些只是预留
- 当前优先真实支持：
  - JSON
  - Markdown
  - TXT
  - HTML
- 可以预留但不强行承诺立刻实现：
  - DOCX
  - PDF

### 5. 页面文字要中文化
- 前端交互文案尽量使用中文
- 减少专业英文直接暴露给用户
- 例如不要默认把这些词直接显示给用户：
  - trace
  - checkpoint
  - metrics
  - approval gate
  - circuit breaker
- 可转成：
  - 流程轨迹
  - 流程存档
  - 运行数据
  - 审核环节
  - 异常保护
